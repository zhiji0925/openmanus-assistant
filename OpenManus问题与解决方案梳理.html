1. 总览：从提问到交付

一次任务大致经历：配置/环境 → 规划与工具调用 → 搜索或浏览器取证 → 步数结束或提前终止 → 产出 Markdown 报告。

2. 环境与依赖

问题
用虚拟环境会不会比主环境效果差？导入失败、Playwright 缺浏览器、Daytona 权限等问题也曾出现。
方案
  • 能力不取决于 venv 本身，取决于依赖是否齐全、解释器是否选对。
  • 长期推荐项目 .venv，用 .\.venv\Scripts\python.exe main.py 运行。
  • Cursor/VS Code 状态栏选择同一解释器，避免终端和 IDE 混用两套 Python。
  • Daytona 需 Full Access API Key；沙箱健康检查用准确 READY 状态与 /api。

3. 模型与视觉识别

问题
  • 配置写成 DEEPSEEK-V4.1-FLASH，DashScope 返回 model_not_found。
  • 日志警告：模型不支持图像，视觉理解被关闭。
方案
  • 正确模型 ID 为小写：deepseek-v4.1-flash（大小写敏感）。
  • 官方文档确认 V4.1 Flash 支持 Vision；警告来自白名单未收录。
  • 已在 app/llm.py 的 MULTIMODAL_MODELS 加入该模型；无图请求不再误报警告。

4. 搜索质量与引擎策略

问题
查「2025 年 AI 趋势」却落到百度百科「2025年」、节假日页面；Google 常失败，回落 Bing 后中文年份词被当成百科词条。
方案
  • 常规顺序：google → baidu → bing → duckduckgo。
  • SerpAPI 不在常规轮询中；仅当前面结果失败或明显不可靠（年份百科、节假日等）时才调用，节省配额。
  • SerpAPI 的 hl=zh 需映射为 zh-cn，否则 HTTP 400。
flowchart TD Q[用户检索 query] --> G[Google 抓取] G -->|成功且可靠| R[返回结果] G -->|失败| B[百度] B -->|成功且可靠| R B -->|失败或不可靠| N[Bing / DuckDuckGo] N -->|仍无可靠结果| S[SerpAPI 兜底] S --> R N -->|有可靠结果| R

5. 浏览器自动化

5.1 机票动态页抽不到数据

问题
携程/去哪儿列表靠 JS 异步加载；自动化打开后 extract_content 常只看到版权或搜索框，模型于是换 Google Flights 或手机站。
方案 / 认知
  • 这是站点特性 + 反爬，不完全是配置错误。
  • 应优先桌面列表页，用点击/等待/滚动触发加载，再抽取。
  • 避免主动跳转 m.ctrip.com 等手机版。

5.2 彩色编号框

问题
界面与日常 Chrome 不同；有时没有编号框，也很少滚动加载更多。
方案
  • 彩色序号是 browser-use 为 click_element 画的标注，不是网站原生 UI。
    • flowchart LR A[扫描可点击元素] --> B[页面画彩色编号框] B --> C[模型选择 index] C --> D[click_element / input_text] E[extract_content] --> F[只抽文字] F --> G[不画编号框]
  • 修复：get_state(cache_clickable_elements_hashes=True)，否则元素扫描失败、编号出不来。
  • 提示词改为：有编号优先点击；列表不全先滚动；内容出现后再 extract_content。
  • 截图只在内存中以 base64 存在，默认不落盘到 workspace。

6. 报告生成策略

问题
  • 自动生成的「任务重点报告」像过程流水账（「让我继续检查…」）。
  • Agent 常把 20 步用在排查，没写出专题 .md。
方案（按你的规则）
  • 资料够了：提前写详尽报告并 terminate，不必跑满 20 步。
  • 资料一直不齐：可以排查到第 20 步。
  • 满 20 步后：用本轮全部素材调用 LLM 生成详尽完整报告（2 与 3 合并为一件事）。
  • SEO 类报告结构：核心结论 → 问题优先级 → 可操作建议 → 证据。

7. 超时、卡住与空响应

7.1 「严格 5 秒限制」

问题
模型说「网络抓取受严格 5 秒限制」，改用短超时 curl。
方案
这是 python_execute 默认超时 5 秒，不是网站限速。已改为 30 秒。

7.2 写报告 Validation error

问题
满步数后生成报告时出现 Empty or invalid response from LLM / Validation error。
方案 / 原因
  • 接口偶发空正文；或思考内容占满 max_tokens=8192，正文为空。
  • tenacity 会重试；日志中可见第二次成功并写出完整报告。
  • 若仍频繁失败，可提高 max_tokens 或关闭/缩短思考输出。
sequenceDiagram participant M as main.py participant R as ensure_detailed_report participant L as deepseek-v4.1-flash M->>R: 满20步，强制汇总 R->>L: ask(全部素材) L-->>R: 空 content R-->>R: Validation error / 重试 R->>L: ask 再次请求 L-->>R: 完整 Markdown R-->>M: 保存 任务完整报告_*.md
